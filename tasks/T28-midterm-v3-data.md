## 要补的数

1. **调优题上还剩哪些错。** SQL-L1-tuned、SQL-L1-tuned-instr 在 49 道调优题上的非正确作答清单（题号、次数、3 次里对几次），按 `reports/attribution/l1plus-codebook.md` 的五类 + 单列人工归类（Codex 人工判，不调模型）。
2. **管理层 / 分析师两类问题分开报。** 先写明两类的定义和题数（取题库标注），再报 SQL-L1、SQL-L1plus、SQL-L3a、SQL-L1-tuned、SQL-L1-tuned-instr 在两类上的准确率（主表、留出各一列）。
3. **两条路的重叠，换口径重算。** 留出题里 L1「3 次中至少错 1 次」的题，分别按「L1plus 修好」「tuned 修好」（修好 = 正确次数比 L1 多）交叉成四格；原口径「L1 多数次答错」也保留一列。两条路都没修好的题，列出它们在 T22b 归因（`reports/results/l1plus-error-attribution.md`）里的类别。
4. **一直错，细分两种。** 每个单元里「3 次全错」的题：3 次结果相同（同一种错法）还是不同（每次错得不一样）。按执行结果的行集比较，有执行报错的单列。
5. **思考 token 信号的可靠性。** 对 SQL-L1 首轮思考 token 的 AUC（0.755，`reports/results/confidence-calibration.md`）：
   - 按题做聚类自助法给 95% 区间（同一题的 3 次一起抽）；
   - 拆开「题间」和「题内」：同一题的 3 次作答里，想得最久的那次是否更容易错；
   - 门槛表：思考最长的 10%、20%、30% 作答拿掉后，剩下的准确率和被拿掉的那些里错答占比。
   同样的分析在 SQL-L1plus 上再做一遍。
6. **宽松口径。** SQL-L1plus、SQL-L3a 按 v3 补评（T23 的待办，评分器不改）；再给一个上界：把 T22b 两家都判为「只是呈现不同」的错答算对后的准确率。两个数分开写，上界写明是归因判断、不是评分器。
7. **agent 的查库调用按档列表。** SQL-L0-E、SQL-L1-E、SQL-L2-E：每次查库调用的用途分布（查明细样例、查枚举值、先把答案算一遍、其他），沿用 T24 的分类规则；与对应直答单元同题同次序配对的「由错变对 / 由对变错」次数；这些翻转里有多少落在直答单元「时对时错」的题上。
8. **自信地答错。** 把 T24 已做的自评把握 × 题型 × 稳定性交叉，整理成一张表。
9. **新增 22 题补了什么。** 按题库覆盖标注，列出这 22 题各补了哪些覆盖类别（只写类别和计数）。
10. **费用汇总。** 按 `runs/INDEX.md` 汇总本期全部付费运行的实际费用：总计，以及按卡分列。
11. **v2 / v3 并排表。** 全部单元主表准确率的 v2、v3 两列（L1plus、L3a 用第 6 项的补评）。
