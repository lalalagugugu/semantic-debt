## A 带权重的取舍

- 基座：SQL-L1plus（`semantic-v1.6-l1plus`）。模型、语义上下文、其余作答要求、「执行报错发回修一次」都不变。
- 系统提示只加一条，原文如下（`k` 代入数字，`k/(1+k)` 写成百分数）：

  > 计分规则：每道题独立计分。答对得 1 分，答错扣 k 分，只输出 CANNOT_ANSWER 得 0 分。请让本题的期望得分最高：只有当你判断自己答对的可能性高于 k/(1+k) 时才作答，否则只输出 CANNOT_ANSWER。题面有歧义时，可以在「假设：」里写明你采用的理解再作答。

- 两个单元：`SQL-L1plus-sel-k1`（门槛 50%）、`SQL-L1plus-sel-k3`（门槛 75%）。109 题 × 3 次。
- 改动系统提示要另打 harness tag（建议 `harness-sel-v1`，由用户打），打之前给出两个单元系统消息的哈希，并证明 SQL-L1plus 的系统消息哈希不变。
- 评分器不改：CANNOT_ANSWER 按现有 `refused` 处理。计分（+1 / −k / 0）在报告脚本里算。

### 正式运行与报告

每个单元报（主表 98、留出 49、109 各一列，v2 评分为主）：

1. 作答比例；作答部分的准确率；用户拿到错答的比例（错答 ÷ 全部作答次数）；每题平均得分（+1 / −k / 0），并与 SQL-L1plus 原结果按同一规则算的得分比较（按题配对自助法区间，同 `reports/results/tuning.md`）。
2. **机械对照**：在 SQL-L1plus 原作答里，把首轮思考 token 最多的一批当作「不答」，数量与该单元的拒答数相同，比较剩下作答的准确率。
3. 事先写死的判定：
   - 「会取舍」：作答部分准确率与每题平均得分都高于 SQL-L1plus 原结果，且区间不含 0；
   - 「不随权重调整」：两档作答比例之差的区间含 0；
   - 「不理会计分规则」：两档拒答都不到 5%。

## B 声明假设、按假设认可（免费）

1. **B1 题目标注**（读题库，Codex 人工）：109 题逐题标「题面是否允许多种合理理解」；允许的，列出每种理解及其参考答案（SQL 与结果）。先报题库里已有多份参考答案的题数，以及它们是否覆盖这些理解。标注先提交、冻结，再看任何作答。
2. **B2 按假设认可的评分**（敏感性分析，不替换主评分）：一次作答同时满足以下两条才算对：声明的假设对应 B1 的某种理解；结果与那种理解的参考答案一致。假设与 SQL 不符、或不在清单里，不算。两个方向都报：
   - 新认可：原来判错、按假设算对；
   - 撤销：原来对上某份参考答案，但声明的假设与那份不符。
   假设对应哪种理解由 Codex 人工判，不调付费模型。SQL-L1plus 原结果与 A 的两档都按 B2 再算一遍。
