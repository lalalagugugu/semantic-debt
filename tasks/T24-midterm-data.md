1. **稳定性分布（③）**：每个已跑单元，三次全对 / 全错 / 时对时错的题数与占比；定义一个稳定性指标（例如时对时错题占比）并说明。
2. **C4 时对时错的题为什么不稳**：SQL-L1 的 20 道时对时错题，逐题比较三次作答的差异（读法不同、表或列选择不同、执行报错、呈现形态），归成几类计数。
3. **C5 自评把握细看**：在 `reports/results/confidence-calibration.md` 基础上，按题型 / 根因类别 / 稳定性交叉，说明「肯定对」档里错的是哪类题。
4. **C6 探查 agent 到底修了什么**：按流向（错→对、对→错、报错→对、报错→错）而不是净数，统计 -E 相对直答的变化；探查调用里枚举查值、行数检查等用途的分布。
5. **C7 L1 vs L2 含 / 不含 19 题**：19 题清单见 `reports/validation/metric-text-vs-impl.md`；SQL-L1、SQL-L2、JSON-L2、L2-E 各算两遍，同题配对差与区间。
6. **token 与费用（④）**：每个单元的平均输入 / 缓存命中 / 输出（含思考）token、每题费用；注明 DeepSeek 缓存计价的前提，并估算缓存不命中时的费用。
7. **数据集规模与数据质量清单（⑥）**：表数、字段数、各表行数；数据质量问题逐项列出（孤儿行、取值大小写不一、层级成环、产品编码缺失等），每项给出受影响行数与查询。
8. **名词表（①）与数字来源表（②）**：`reports/midterm/glossary.md`（档位、单元、直答、探查 agent 等，给非技术读者）；`reports/midterm/numbers.md`（中期报告引用的每个数字 → 来源文件、行、命令）。
