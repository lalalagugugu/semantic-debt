## 目标

写一个确定性的结果比对器，并用外部基准公开的 600 条候选 SQL 验证它的判定是否合理。

## 比对规则（来自设计 v5，不得自行改动）

1. 执行候选查询，与参考结果比对完整结果集（不截断）。
2. 数值相对误差 0.5% 以内算相等；字符串去首尾空格后比较。
3. 不看列名和列顺序；候选多出的列不扣分；参考的每一列都要在候选里找到取值一致的一列。
4. 只有问句要求排序或「前 N 名」时才比较行序；「前 N 名」在第 N 名有并列时，并列者任一都算对。
5. 小数与百分数等价（0.9967 与 99.67）。
6. 一道题可以有多份参考结果（「可接受解读」），与任一份一致就算对。
7. 输出四种结果之一：`correct`、`wrong`、`exec_error`、`refused`（候选输出 `CANNOT_ANSWER`）。准确率只把 `correct` 记为 1。

## 交付物

1. `harness/scorer.py` 及单元测试（覆盖上面每条规则，至少各两个用例）。接口：`score(candidate_rows, refs, rules) -> outcome`，不依赖具体执行器。
2. `reports/validation/scorer_check.md`：对 600 条候选（6 个系统 × 100 题）在我们的数据上重新执行并打分，与对方公布的严格判定、宽松判定逐条对比，列出所有不一致并归类：我们更宽（如并列、百分数）、我们更严、我们的 bug（必须修掉）。报告里只写题号和归类，不写题目原文。
3. 执行候选 SQL 用 `$SEMDEBT_DATA_DIR/chdb-eval`（不要打开 `$SEMDEBT_DATA_DIR/chdb`，那份给 Claude Code 用）。

## 验收

- 单元测试全过。
- 与对方严格判定的一致率 ≥ 95%（不计我们规则有意更宽的情况），每条不一致都有归类和理由。
