# T15 探查 agent（L0-E、L1-E、L2-E）

- 状态：未开始
- 负责：Claude Code
- 模式：普通（`scripts/start-card.sh T15`）
- 依赖：G3；L2-E 另需 T16 的 `cube_sql` 执行器
- 预算：Flash 80 元 / Pro 280 元

## 目标

检验「会自己查数据的 agent」能不能替代一部分治理，以及有了指标层之后它还有没有用：在 L0、L1、L2 上给模型一个只读的查询工具，看它能把多少差距补回来、要多付多少 token 和时间。

## 规格

- 与对应直答单元相同的系统提示和语义上下文，另加一个工具 `run_sql(query)`：只读（拒绝任何写操作和 DDL），每次最多返回 50 行，30 秒超时。
- 由模型决定查不查、查什么、何时交卷；最多 8 步工具调用，之后必须给出最终查询；最终查询按直答的规则执行和修正一次。
- 单元与工具后端：SQL-L0-E 和 SQL-L1-E 的 `run_sql` 走 `chdb_retail`；SQL-L2-E 的 `run_sql` 和最终查询都走 `cube_sql`（T16）。
- 系统提示里只增加一段工具说明，不增加任何关于数据的提示。这段说明在开跑前写好，打 tag `harness-agent-v1` 冻结，并原文列进报告。
- 中文题集全部，每题 3 次。

## 交付物

- `runs/<run-id>/` 下三个单元的 JSONL，每条另记步数、每步的工具调用、总 token、总耗时。
- `reports/results/explorer.md`：三个单元的准确率与四种结果占比，与直答 L0、L1、L2 对比；按题目的「语义依赖」（可从数据发现 / 只能由业务告知）分开列；每题平均步数、token 与耗时（agent 税）。

## 验收

- 记录数 = 题数 × 3 × 3，无缺失。
- 工具调用全部是只读的（日志核对）。
