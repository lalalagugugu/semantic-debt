# T19 评分、失败归类与报告

- 状态：未开始
- 负责：Claude Code + 用户抽检
- 模式：普通（`scripts/start-card.sh T19`）
- 依赖：T13–T18
- 预算：80 元（V4 Pro 做裁判与归类）

## 目标

把所有运行结果变成可以下结论的表和图，并按设计里预先写好的「结果 → 决定」表给出结论。

## 口径（来自设计 v5，不得自行改动）

- 每次作答的结果是四种之一：对、错答、执行失败、拒答。只有「对」记 1 分。
- 准确率 = 答对的作答次数 ÷ 全部作答次数（题数 × 3）。
- 每个单元报四种结果的占比（合计 100%），另报首次即对率（修正前）、三次全对率。
- 汇总层（SQL-L1.5S）和 JSON 接口另报覆盖外的拒答率与错答率。
- 差距按 5 / 15 个点分三档解读，不做显著性检验；分层结果与只用半数题的 C2 标为探索性。

## 做法

1. **宽松判定**：统计类和开放式题，用 V4 Pro 做裁判；裁判拿到问句、可接受解读清单、参考结果和候选结果。用户抽检 20%。若被测模型也是 Pro，在报告中注明。
2. **失败归类**：每个单元第一次运行的失败，用 V4 Pro 初判为：选错表或字段、路径错、口径错、筛选错、粒度错、语法错、接口表达不了、汇总层未覆盖、读错问题、拒答；另标「错答但已声明假设、偏差可见」。用户抽检。
3. **汇总表**：每个单元的上述指标；按 Q 级、复杂度来源、语义依赖、用户类型、汇总层覆盖分层。
4. **撞墙热力表**：行是复杂度来源，列是 16 个单元，格子是准确率和题数；某单元在某类题上低于 50%、或比它自己的平均低 20 个点以上，标为撞墙。
5. **按对比下结论**：C1–C9 逐条给出结果和对应的决定。
6. **投入产出**：汇总各卡记录的工时（写 L1、明细宽表、汇总层、指标、调优），与对应的准确率提升并列。
7. **成文**：一页中文结论 + 英文摘要。

## 报告必须写到的

- 主问题的说法：「已经有宽表和汇总表，还要不要建指标层」（C3、C4）。
- OSI（Open Semantic Interchange）：统一 YAML 与它的关系；第一期为什么统一呈现格式，第二期如何比较几种序列化（建表语句加注释、TMDL、Power BI MCP 的输出、YAML）。
- 三种作答方式的定义（直答、探查 agent、规划 agent）和 agent 税。
- 投入产出：各档的工时与准确率提升。
- 局限：一个模型、约 25 张表、中文问句；Contoso 本身很干净，真实的坏交付比 L0 更坏。

## 必须写进报告的事（前面各卡交接，截至 2026-10-16）

这些不是可选的讨论点，是**不写就会被误读**的东西。

1. **L0 删掉的关系对「能否连表」影响有限。** 同一列在所有表里映射到同一短名，所以被删的关系仍可由同名键推断（`gk = gk`）。L0 的损害主要在**语义**（不知道 `amt1` 是什么），不在结构。不写这句，读者会把「删了 1/3 关系」误读成「三分之一的连接做不了」。（T09，PR #24）
2. **L0 / R 的上下文只有 L1 的十分之一**（约 3.6–4.0k vs 约 40k token，见 `reports/validation/context_sizes.md`）。「坏交付」省下的不只是文档工夫，还有每次调用的输入成本；它换来的准确率损失正是本实验要量的。设计里没有这一项，是实测发现。
3. **L1.5S 的列描述保留了明细表的血缘注记**，这是有意的——真实的汇总层文档本来就写血缘，删掉等于人为阉割这一档、让它的成绩偏低。收窄可见范围由**执行范围**保证（T11 的库级限制），不由删描述保证。见 `decisions/2026-10-16-l1_5s-lineage-and-execution-scope.md`。
4. **统计「模型尝试够明细表」的次数**（L1.5S 单元里被库级限制拒掉的查询）。这是「汇总层在这道题上不够用」的直接证据，是 C4 要的信号，不是噪声。
5. **格式敏感性是上界，不是第二套判定。** 同时报「严格口径 X%」与「放宽字符串格式后 Y%」，并写明 Y 是上界——数值对上、标签不同，也可能是模型把对的数配到了错的实体上。（T02）
6. **评分器与外部基准的一致率**：86.7% / 88.3%（历史）与最终 521/594（87.7%）、排除 11 条有意更宽后 521/583（89.4%）全部保留。并说明差异的结构：我们在四处**故意更严**（参考的每一列都要有、完整结果集、要求排序时比行序、容差 0.5%），而「有意更宽」那 11 条是我们自己选择的。（T02，`decisions/2026-10-14-scorer-contract-and-acceptance.md`）
7. **近零量的相对误差**：冻结规则第 2 条已加量纲绝对下限，但仍有约 21.72% 的数值参考列落在 `other`（无绝对下限）。这部分仍可能受末位舍入影响。（T02）
8. **Q43 接受两种地理粒度解读**，该题从此不测地理粒度能力；同类歧义在 100 道源题里仅此一例。（`decisions/2026-10-15-g0-passed.md`）
9. **DAX 与 Cube 在几处行为不同**（配额场景默认、环比位移、新客口径、4 个依赖较新查询计划器的指标），是引擎限制而非上下文差异，已列在 `render/README.md`。跨栈比较时必须引用，否则会把引擎差异算到档位头上。（T10、T16、T17）
10. **数据校验**：87 题直接一致、12 题不一致全部具名解释、**底层数据不一致 0 题**；这道检查是跨厂商的（Claude Code 导入、Codex 校验）。（T03，`decisions/2026-10-15-g0-passed.md`）
11. **执行超时**定在多少、因此有多少次失败属于超时而非答错。（T11）
