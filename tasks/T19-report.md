# T19 评分、失败归类与报告

- 状态：未开始
- 负责：Claude Code + 用户抽检
- 模式：普通（`scripts/start-card.sh T19`）
- 依赖：T13–T18
- 预算：80 元（V4 Pro 做裁判与归类）

## 目标

把所有运行结果变成可以下结论的表和图，并按设计里预先写好的「结果 → 决定」表给出结论。

## 口径（来自设计 v5，不得自行改动）

- 每次作答的结果是四种之一：对、错答、执行失败、拒答。只有「对」记 1 分。
- 准确率 = 答对的作答次数 ÷ 全部作答次数（题数 × 3）。
- 每个单元报四种结果的占比（合计 100%），另报首次即对率（修正前）、三次全对率。
- 汇总层（SQL-L1.5S）和 JSON 接口另报覆盖外的拒答率与错答率。
- 差距按 5 / 15 个点分三档解读，不做显著性检验；分层结果与只用半数题的 C2 标为探索性。

## 做法

1. **宽松判定**：统计类和开放式题，用 V4 Pro 做裁判；裁判拿到问句、可接受解读清单、参考结果和候选结果。用户抽检 20%。若被测模型也是 Pro，在报告中注明。
2. **失败归类**：每个单元第一次运行的失败，用 V4 Pro 初判为：选错表或字段、路径错、口径错、筛选错、粒度错、语法错、接口表达不了、汇总层未覆盖、读错问题、拒答；另标「错答但已声明假设、偏差可见」。用户抽检。
3. **汇总表**：每个单元的上述指标；按 Q 级、复杂度来源、语义依赖、用户类型、汇总层覆盖分层。
4. **撞墙热力表**：行是复杂度来源，列是 16 个单元，格子是准确率和题数；某单元在某类题上低于 50%、或比它自己的平均低 20 个点以上，标为撞墙。
5. **按对比下结论**：C1–C9 逐条给出结果和对应的决定。
6. **投入产出**：汇总各卡记录的工时（写 L1、明细宽表、汇总层、指标、调优），与对应的准确率提升并列。
7. **成文**：一页中文结论 + 英文摘要。

## 报告必须写到的

- 主问题的说法：「已经有宽表和汇总表，还要不要建指标层」（C3、C4）。
- OSI（Open Semantic Interchange）：统一 YAML 与它的关系；第一期为什么统一呈现格式，第二期如何比较几种序列化（建表语句加注释、TMDL、Power BI MCP 的输出、YAML）。
- 三种作答方式的定义（直答、探查 agent、规划 agent）和 agent 税。
- 投入产出：各档的工时与准确率提升。
- 局限：一个模型、约 25 张表、中文问句；Contoso 本身很干净，真实的坏交付比 L0 更坏。
