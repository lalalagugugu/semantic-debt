# T11 SQL harness

- 状态：进行中（代码与离线验收完成；真实题目加载与真实 API 冒烟待用户放行，见记录）

## 目标

实现直答的 harness：组装 prompt、调用 DeepSeek、执行、报错修正一次、评分、记日志。后续 DAX、Cube、探查 agent 都复用它，只换执行器和语法说明。

## 规格（来自设计 v5，不得自行改动）

1. **prompt 顺序**（为了命中缓存，不变的放前面）：系统提示（角色、输出格式、本栈语法说明）→ 本单元的语义上下文 → 用户消息（一道问题）。
2. **输出格式**：一个查询代码块，加一行以「假设：」开头的说明；答不了只输出 `CANNOT_ANSWER`。
3. **执行**：报错时把报错信息作为下一条用户消息发回，让模型修正一次；修正前后的结果都记录。不因为答案错而重试。
4. **模型参数**：思考模式开启（默认 high），不设置 temperature；记录接口返回的模型版本、输入 token（区分缓存命中）、输出 token、耗时。
5. **重复**：每题独立跑 3 次，互不共享上下文。
6. **执行器接口**：`execute(query) -> rows | error`。先实现 chDB 的三个执行器：`chdb_retail`（库 `retail`，L0 用库 `l0`）、`chdb_ads`（只允许引用库 `ads` 里的表；引用其他库的表时返回一条普通的执行报错，照常发回模型）。为 Cube SQL、Cube JSON、DAX 预留同一接口。
7. **日志**：`runs/<run-id>/<cell>.jsonl`，一次作答一行：题号、单元、第几次、模型版本、题库提交号、提取的查询与假设、修正前后的执行结果摘要、评分结果、token、耗时、原始响应的哈希。**不含题目原文**。完整原始响应（含思考内容）写到 `$SEMDEBT_DATA_DIR/runs-raw/<run-id>/`。
8. **断点续跑**：中断后重跑同一 run-id 只补缺失的行。
9. **dry run**：`--dry-run` 只统计调用次数，按实测或配置的 token 估算费用并打印。
10. **并发**：可配置，默认 8；遇到限流自动退避。
11. **评分**：调用 T02 的 `harness/scorer.py`，不得自己另写比对逻辑。准确率 = `correct` 次数 ÷ 作答次数。
12. 题目从 `$SEMDEBT_EVAL_DIR/questions/` 读取，路径不得写死。

## 来自前面卡片的硬要求（T10 交接，2026-10-16）

**一、每个单元有允许的库范围，执行器拒绝越界查询。**

chDB 的同一个数据目录里有四个库，模型只要写 `retail.FactOnlineSales` 就能绕过 L1.5S 的全部收窄——那会毁掉这一档。

| 单元 | 允许的库 |
|---|---|
| R、L1 | `retail` |
| L0 | `l0` |
| L1.5W | `dwd` + `retail`（设计上原始表仍可见） |
| **L1.5S** | **只有 `ads`** |

默认库设为该单元的库；显式引用其他库的查询**执行前静态拒绝**，记为 `exec_error` 并单独归类（不要混进模型写错 SQL 那一类）。**必须有测试**：从 L1.5S 单元查明细事实表必须失败。

L1.5S 的列描述里保留了血缘注记（提到明细表名），这是**有意的**——见 `decisions/2026-10-16-l1_5s-lineage-and-execution-scope.md`。安全性由本条的执行范围保证，不由删描述保证。

**二、语义上下文放在 prompt 的稳定前缀里，并记录缓存用量。**

同一单元内 122 道题共用**完全相同**的上下文前缀。顺序固定为：系统提示 → 语义上下文 → 语法说明 → 题目（题目在最后）。不得在上下文里插入随题变化的内容，否则 DeepSeek 的上下文缓存全程不命中。

日志里**分别记录 cache hit 与 miss 的 token 数**（接口返回里有），T12 用实测用量重估预算。背景：L1 档的上下文实测约 40k token，是设计估算（约 10k）的 4 倍，见 `reports/validation/context_sizes.md` 与 open question `T10-2`。**在 T12 用实测数字重估之前，不要开 T13 的全量跑。**

**三、执行超时要定成显式参数。**

外部基准的 Q33 在本地要 89.457 秒（对方那边超时）。定 60 秒这题在所有单元全军覆没、且与语义层质量无关；定 120 秒拖慢约 14,000 次调用。把超时写成参数、记进决策，超时失败**单独归类**，不要算成 `wrong`、也不要算成模型的错。见 `decisions/2026-10-15-g0-passed.md`。

**四、透传评分器要的元数据。** 题目记录里的 `rules`（含 `ordered`、`top_n`、`value_kinds`、`value_types`）**原样透传**给评分器，不解释、不补全。整数计数守卫依赖 `value_types`，少一个就失效。见 `decisions/2026-10-14-scorer-contract-and-acceptance.md`。
