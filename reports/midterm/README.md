## 1. 为什么做这个实验（Motivation）

- 厂商都在讲智能问数：大模型越来越强，agent 能自己查库，语义层、指标层是标配……
- 落到企业里，大家在等一个「最合适的时机」再动手。等什么？
  - 等**模型**更强？
  - 等 **agent / harness** 更聪明：会探查、会规划、会写 Python？
  - 还是什么都别等，**现在就闷头做数据治理**？要做的话，先做哪一块：改名、写描述和口径、建宽表、建汇总层、建指标层？
- 这些问题没有公开的、可复现的对照数据。我们做了一套：同一个模型、同一批题，只换一个变量，看准确率变多少、花多少钱。

【待补：一两句讲清楚读者是谁（数据负责人、BI 负责人、问数项目负责人），读完能做什么决定】

## 2. 结论先行

按我们开始时的问题来组织：**现在该等什么、该做什么。**

### 2.1 不用等模型：会写 SQL 已经不是瓶颈

- 模型写主流 SQL 的能力已经够用：首轮报错大多是一条引号规则没教，报错发回去修一次之后，最终执行失败几乎为零。
- 再教写法，用规则、样例、同类题样例都试过，准确率没有可测到的提升。剩下的错误都是**查询能执行，但结果不对**。
- 外部旁证：DeepSeek-R1 论文观察到 few-shot 会降低推理模型的表现。【待核对原文措辞与出处】
- 例外：模型不熟的查询语言（指标层 DSL），说明写错会直接变成执行失败。【待补：SQL-L2 新旧说明对照】

### 2.2 不用等 agent：会查库的 agent 替代不了治理

- 让模型自己查库探查（最多 8 步），在坏文档和好文档上都只多对 0.7 个点，费用多约 40%。
- 坏文档 + agent，离好文档直答还差 28 个点。
- 【待补：指标层 + agent（L2-E）】【第二期：会规划、会写 Python 的 agent】

### 2.3 现在就该做治理，但要做对的那一块：口径和约定

| 治理动作 | 准确率变化 | 结论 |
|---|---|---|
| 只改名（坏名 → 业务名） | +3.8 | 不够 |
| 写描述、枚举含义、企业约定、口径 | +24.8 | **主要收益** |
| 建明细宽表 | −1.0 | 没有额外帮助 |
| 只给汇总层 | 覆盖内 −7.1（补齐约定后），覆盖外多为拒答或错答 | 不能代替明细 |
| 建指标层（L2） | 【待补】 | 【待补】 |

- 收益几乎全部落在「只能由业务告知」的题上。「可以从数据里发现」的题，模型自己就能做对大半。
- 一次写好的通用文档，在外部基准原题上不输给为那套题专门写的文档；换到新题，专用文档掉了 15 个点，我们的通用文档几乎不掉。
- 指标的文字口径普遍留有不止一种读法（69 个指标里 14 个），写口径时要写到「只有一种算法」。

## 3. 实验方法

### 3.1 数据与题目

- 数据：公开零售数仓样例（来源与许可见 `vendor/`）。【待补：一句话描述规模】
- 题目：122 道中文问题。外部基准改写 100 道，新写 22 道（按企业约定和真实问法补写）。
  - 13 道开放分析题（judge 题）不进主准确率，第二期再评。
  - 主表 98 道；另有 11 道低区分度题单列。
  - 按难度分 Q1、Q2、Q3，按用户类型分管理层与分析师。
  - 调优集与留出集各一半。
- 隔离：语义层由看不到题目的会话「盲写」（G1 之前不能读题库），避免照着考题写文档。

### 3.2 变量（单元 = 栈 × 档位 × 作答方式）

| 维度 | 取值 |
|---|---|
| 语义层档位 | L0 坏交付 / R 只给表结构 / L1 完整文档 / L1c 外部基准自带文档 / L1.5W 加明细宽表 / L1.5S 只给汇总层 / L2 指标层 |
| 查询语言与接口（栈） | ClickHouse SQL；Cube SQL API（SQL-L2）；Cube JSON（JSON-L2）；DAX（待测） |
| 作答方式 | 直答（报错时修一次）；探查 agent -E（最多 8 次 `run_sql`）；规划 agent -P（第二期） |
| 写法说明深度（C13） | 1 规则 / 2 条件与禁忌 / 3 通用样例 / 4 同类题样例 |

### 3.3 模型与运行

- 模型：DeepSeek-V4.1-Flash（接口名 `deepseek-flash`，指纹 e72d3c7f…），思考模式开启。G3 时对比过 V4-Pro 后选定。
- 每题 3 次；错峰运行；总费用【待补：截至 10-19 正式运行约 45 元，含试跑与作废启动约 57 元；T16、L2-E 未计】。

### 3.4 评分与独立核对

- 四种结果：对、错答、执行失败、拒答。只有「对」记 1 分。
- 评分器、参考答案、报告数字都由「另一家」的工具独立重算：Codex 写、Claude 核，或反过来。评分器 v2 由两家各自实现，逐条对账 0 分歧。
- 解读阈值：差 5 个点以内不解读，5–15 看方向，15 以上算大；按题配对，给出自助法 95% 区间（探索性）。

### 4.8 与产品做法的对照

- Power BI「Prep data for AI」三件套：
  - AI data schema ≈ 暴露面的选择（L0 vs L1、L1.5S）；
  - AI instructions ≈ L1 的约定与口径；
  - verified answers ≈ 高频问题的已核对答案库，本实验没有测，留出集按设计也测不到。
- 国内指标层与 DSL 厂商：指标命中走指标层，不命中退回明细 SQL，靠工单补指标。对应我们的回退链与 JSON-L2 覆盖表。
