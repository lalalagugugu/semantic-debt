# 失败归类编码手册（T19b，SQL-L1）

依据：`decisions/2026-10-20-l1-error-attribution.md`；`docs/design-v5-public.md` 的失败归类一节。

用途：Flash 初判与 Codex 独立复核用同一份手册。每条作答单独归类：同一题的三次作答可能错法不同。

每个条目给出四项标签：

| 标签 | 取值 |
|---|---|
| 类别 | 10 类，选 1 |
| 已声明假设 | 是 / 否 |
| 根因 | 5 个，选 1 |
| 文档证据 | L1 上下文中的位置，或「未找到」 |

## 判定材料

判定只看以下材料：

- 题面；
- L1 上下文，与 SQL-L1 运行时给模型的相同；
- 参考 SQL 及其解读；
- 参考结果前若干行；
- 作答的最终 SQL，及其结果前若干行（执行失败时给报错）；
- 作答随答案写出的「假设」说明；
- 评分器的 `reason`。

不看原作答的思考内容。

「作答」指最终提交的那一轮。执行报错后修过一次的，只看修后的那一轮。

评分器的 `reason` 只是线索，类别不由它决定：

| reason | 含义 |
|---|---|
| `row_count` | 行数不同 |
| `values` | 数值对不上 |
| `missing_columns` | 缺参考答案要求的列 |
| `selection` | 选出的对象不对 |
| `order` | 顺序要求不满足 |
| `rank` | 名次不对 |

## 一、类别（10 选 1）

按「作答与参考答案的第一处实质差异」归类。有多处差异时，取对结果影响最大的一处。影响相当时，按下表从上到下的顺序取先出现的一类。

| # | 类别 | 判定标准 | 边界 |
|---|---|---|---|
| 1 | 汇总层未覆盖 | 只用于汇总层单元：所需数据不在可见的汇总表里 | SQL-L1 看得到全部明细表，**本卡不应出现**。若出现，说明判错了单元 |
| 2 | 接口表达不了 | 所用查询语言或接口无法表达所需计算 | SQL-L1 用的是完整的 ClickHouse SQL，**本卡原则上不应出现**；只有确认 SQL 本身做不到时才用 |
| 3 | 语法错 | 最终一轮执行失败，原因是语法、标识符写法、函数用法等书写问题，而非选错对象 | 执行失败但根源是表名或列名选错（对象不存在）的，归「选错表或字段」 |
| 4 | 读错问题 | 作答回答的不是题目问的东西：问 A 答 B、漏掉题目明确要求的一部分、把题意理解成另一个问题 | 题意理解对了、只是某个指标口径或筛选条件取错的，归对应的具体类别。只有在问题本身被理解偏了时才用本类 |
| 5 | 选错表或字段 | 用了错误的事实表或维度表，或用了错误的列（取了相近但不同的字段、错的度量列、错的属性列） | 同一业务概念、算法不同的，归「口径错」。列对、过滤值错的，归「筛选错」 |
| 6 | 路径错 | 表和列选对了，但关联方式错：连接键错、连接类型错导致多出或丢失行、关联路径绕错、扇出造成重复计数 | 因为缺少过滤而多出行的，归「筛选错」 |
| 7 | 口径错 | 指标的定义或算法与约定不一致：分子分母、是否扣退货或折扣、去重与否、比率的计算方式、时间口径、单位换算 | 只是时间范围或筛选值取错的，归「筛选错」 |
| 8 | 筛选错 | 筛选条件错：范围、取值、包含或排除了某类对象、时间窗口边界、空值处理导致的纳入或排除 | 筛选对、聚合粒度错的，归「粒度错」 |
| 9 | 粒度错 | 分组或输出粒度与题目要求不一致：分组维度多了、少了或错了；该汇总的没汇总；该逐行的被汇总；排名或前 N 的范围错 | 粒度对、行数差异来自筛选的，归「筛选错」 |
| 10 | 拒答 | 最终作答是拒答（`CANNOT_ANSWER`） | 只看最终作答。拒答同样要给根因 |

**兜底说明：**

- 结果只差在呈现上（多出列、列顺序、四舍五入、单位换算后的展示），而评分器判错的，按造成差异的那一处归类，通常是「口径错」或「粒度错」，并在 `note` 里写明「呈现差异」。
- 若怀疑参考答案本身有问题，类别仍按作答与参考的差异来定，根因选 5。

## 二、已声明假设

满足以下两条时标「是」，否则标「否」：

1. 作答的「假设」说明里，明确写出了与参考答案不同的那个取舍，例如采用了哪个口径、范围或对象；
2. 读者只看假设说明就能发现结果与预期的偏差。

泛泛的说明不算，例如「按常规理解」「按数据库数据计算」。拒答一律标「否」。

## 三、根因（5 选 1）

问的是：要答对这一条，缺的是什么。

| # | 根因 | 判定标准 | 文档证据要求 |
|---|---|---|---|
| 1 | 文档没写 | L1 上下文里找不到答对所需的信息：表、字段、关系、枚举含义、约定、指标口径都没有提到 | 写「未找到」，并在 `note` 里说明找过哪些位置 |
| 2 | 文档写了但有歧义 | L1 有相关内容，但可以合理地读出不止一种意思，作答取了其中一种 | 引用那段内容的位置，并在 `note` 里写出两种读法的差别（不复述题面） |
| 3 | 文档写清楚了，模型没理解或没用上 | L1 有明确、只有一种合理读法的内容，作答没有照做；或题意清楚而作答读错了 | 引用那段内容的位置。题意读错且与文档无关的，写「不涉及文档」 |
| 4 | 题面本身有歧义 | 题面允许不止一种合理理解，作答的理解合理、与参考答案不同；与 L1 文档无关 | 写「不涉及文档」，或引用相关位置 |
| 5 | 参考答案或评分可疑 | 作答看起来是对的或同样合理，而参考答案或评分器的判定可疑 | 在 `note` 里写出可疑之处（不复述题面） |

**边界：**

- **1 与 2：** 1 要求根本没有相关内容。只要有相关内容，就不是 1。
- **2 与 3：** 判 3 要求那段文字只有一种合理读法。若需要结合其他段落推断，且推断不唯一，判 2。
- **3 与 4：** 歧义来自题面判 4，来自文档判 2。题面清楚而作答理解错了，判 3。
- **4 与 5：** 题面有两种理解、参考只认其中一种的，判 4。题面清楚、而参考答案的算法或结果本身有问题的，判 5。
- **语法错与执行失败：** 根因通常是 3，因为语法说明在系统提示里写清楚了。L1 上下文没有涉及的引擎行为判 1。
- **拒答：** 拒答理由与 L1 的内容对照：L1 确实缺所需信息，判 1；L1 有而作答认为没有，判 3。

## 四、文档证据的写法

- **位置**：用 L1 上下文（YAML）里的路径式位置，按实际出现的键名写，例如：
  - `conventions#<id>`
  - `datasets.<表名>.columns.<列名>`，或 `datasets.<表名>.when_to_use`
  - `relationships[<序号>]`
  - `multi_path_defaults`
  - `metrics.<名称>`
  - `synonyms`
  - `data_quality`
  - `model.grain_note`
- **多处时**：最多写两处，用「；」分隔。
- **找不到时**：写「未找到」。
- **与文档无关时**：写「不涉及文档」，用于根因 4、5，以及与文档无关的读错。
- **不写原文**：只写位置，不抄录原文；不复述题面、参考 SQL 或作答 SQL。

## 五、输出格式

每条输出一个 JSON 对象：

```json
{"category": "<10 类之一，用上表的中文名>",
 "declared_assumption": true | false,
 "root_cause": 1 | 2 | 3 | 4 | 5,
 "doc_evidence": "<位置>" | "未找到" | "不涉及文档",
 "note": "<一句话，不复述题面>"}
```

Codex 复核输出 CSV，列为：

```
question_id,round,category,declared_assumption,root_cause,doc_evidence,note
```
