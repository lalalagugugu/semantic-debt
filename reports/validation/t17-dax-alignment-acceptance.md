# 检查清单第 2 项：DAX 对齐清单的引擎验收（T17-mac）

- 清单：Codex T16，PR #156（`T16-dax-alignment`，`be9b1dd`），`reports/validation/t16_dax_reference_alignment.md`，用户 2026-10-23 转交。
- 本卡做的：把清单每一行落成**通用探针**（切片不对应任何题，只用年、月、门店、品类、子类、场景这类维度），对照数字由 chDB 直接读 Parquet 按清单写的**参考读法**算出；有其他可能读法的，同时算出其他读法的数字，探测时报告引擎走的是哪一种。共 69 项，在 L2 模型上跑（`windows\t17.ps1 probe -Tier L2` 的「对齐清单验收」一段）；定义在 `harness/dax_probe.py` 的 `alignment_checks`，数字在 `reports/validation/dax_probe_expected.json`（`group = alignment`）。
- 本卡**没做**的：没有改任何度量值。清单说「具体变更由 T17-mac 按裁决实现、提供通用引擎探针，再走冻结版本审批」；改哪种读法、保留哪些筛选，有几处清单本身也留给引擎证据，所以先拿 Windows 上的结果，再由用户裁决（`decisions/open-questions.md` T17-1）。
- 判定：容差 0.5%；「应为空」只认空白；「记录」项（清单没定参考读法的子选择）只报告引擎读法，不计通过与否。

## 预判不符的几处，可能的通用改法（待引擎证据与用户裁决，未实施）

| 问题 | 可能的通用改法 | 影响 |
|---|---|---|
| 场景默认值在事实键分组时残留预算 | 判断「查询筛了场景」时也看事实表的场景键：`ISFILTERED('FactSalesQuota'[ScenarioKey])`（计划收入同理） | 只改 4 个度量值；也可以不改、在 DAX 说明或度量值描述里写「按场景分组用场景维的列」（调用条件） |
| 新客的首购日期受事实日期列与业务切片影响 | 首购日期用 `CALCULATE ( MIN ( 事实[DateKey] ), ALLEXCEPT ( 事实, 事实[CustomerKey] ) )`（只保留客户），截止日从日期维或事实日期列中取窗口最后一天；切片只决定数哪些客户 | 改 3 个度量值；切片内数哪些客户（窗口内买过 / 任何时候买过）要先定 |
| 占比主成员 `ALLSELECTED()` 去掉父组、保留子项筛选 | 清单写明不得全局改写基础指标迎合某一个分母范围。可选：在说明里写调用条件（父组分母用变体或在查询里自己写 `CALCULATE([销售额], REMOVEFILTERS(子层))`）；或加「父组内」变体 | L1 只承诺「全公司、某渠道、某品类内」，加新变体超出 L1 时不能加 |
| 渠道内占比按事实键分组恒为 1 | 分母同时 `REMOVEFILTERS('FactSales'[StoreKey])`；或调用条件「按门店分组用门店维的列」 | 改 1 个度量值 |
| 同店集合随子类筛选重新认定 | 认定门店集合时去掉产品维筛选：集合用 `CALCULATETABLE ( VALUES(…[StoreKey]), REMOVEFILTERS('DimDate'), REMOVEFILTERS('DimProduct'), REMOVEFILTERS('DimProductSubcategory'), REMOVEFILTERS('DimProductCategory'), 年份条件 )`，金额仍在当前切片上算 | 改 3 个度量值 |

任何一项改动都是渲染器（`render/measures.py`）改动，只影响 DAX 产物，需要新的语义层 tag，并重跑探测确认。
