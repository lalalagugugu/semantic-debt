## 二、实现思路

| 部分 | 做法 | 规格 |
|---|---|---|
| 接口 | `score(candidate, refs, rules) → (outcome, reason)`。候选是行集、`CANNOT_ANSWER` 或 `ExecError`；每份参考一份 rules；输出五种判定和原因码，不做敏感性诊断 | 一 |
| rules 校验 | 缺必需字段、旧开关、越界列号、选择身份列不必答等，直接拒绝（报错），不用默认值放宽 | 二、五.7 |
| 单元格 | 字符串去首尾空白；NULL 只等于 NULL；参考返回类型为整数型的列一律精确；其余数值以参考值为基准算容差；×100 与 ÷100 只用于 percentage、ratio 和非整数型的 other 列，参考为 0 时不试；编码精确并接受十进制整数字符串；日期写法归一（含带 `T`、全零小数秒的零点）；参考一侧的空标签只用于字符串列；人名拆合列（含选择身份列） | 三、十一.1、十二 |
| 列的对应 | 先对每个必答列（或可合并的相邻两列）逐个候选列做必要条件筛选：单列能否按多重集配上足够的行。再按固定顺序回溯枚举单射对应，找到即判对；试满 1,000 种还有剩，判 `unscored` | 四、六.5、十一.2、十一.4 |
| 行的配对 | 相同的行先合并成类，类与类之间按「必答列逐列相等」连边。连边时精确列按键分桶，数值列按排序窗口找候选。最后用带上下界的二分 b-匹配（最大流）判可行：参考与候选两侧都分「必须配上」和「可以不配」 | 五.1、六.2、六.3 |
| 可选行 | Top-N 的边界成员、分组选择的参考行、计数为 0 的组（两侧），都化成「可以不配」，统一由上下界流处理，不枚举成员组合 | 五.3、五.4、六.4 |
| 有序 | 参考按 `order_by` 量化键把连续相同的行分块；候选切成连续段，逐段与块做多重集配对。行数固定时线性推进；有可选行时用动态规划推进段的终点 | 五.2 |
| 分组选择 | 身份列一律精确比较，由候选取值直接得出它选了哪些父对象和组内对象，逐组核对：数目、严格前缀、只选参考域内的对象、叶对象不重复、每行落在叶步骤里 | 五.7 |
| 名次 | 竞赛、稠密、位置三种写法各试一次，每次都整份答案统一用一种。竞赛和稠密按块精确比；位置写法要求块内名次不重复，前缀排名还要从块首连续编号 | 五.9 |
| 快路 | 只用无损键（合并相同行时用），不量化。快路不一致不判错，一律进入容差配对 | 十一.5 |

复杂度：
- 不对行做笛卡尔积，名次不做逐位置搜索，列的对应有上限。
- 连边在数值稠密时可能变多。为此单列筛选设了工作量上限，超过就保留这个对应，不剪枝；这不影响判定，只可能让尝试的对应变多。

## 三、规格不清楚的地方（逐条，没有自行补规则；已按第十一节解决的不再列）

**更新（2026-10-19）**：下表 15 条已全部由规格第十二节（#110）裁定，检查器已改为按第十二节实现（提交 `1595ffe`）。与下表原取舍不同的有 6 处：
- 第 1 条：×100、÷100 只用于 percentage、ratio 和非整数型的 other 列；
- 第 2 条：参考返回类型为整数型的列一律精确比较；
- 第 8 条：选择身份列也可以参与人名拆合；
- 第 9 条：空标签只用于字符串列，参考空串对候选 NULL 也算匹配；
- 第 10 条：带 `T` 的零点、全零小数秒的零点都与日期等价；
- 第 11 条：「其余必答数值」不含名次列。

其余 9 条与原取舍相同。下表保留提出时的原文。

| # | 条款 | 不清楚之处 | 检查器的取舍 |
|---|---|---|---|
| 1 | 三.3 | 「小数与百分数等价（×100、÷100）」是否只对 `percentage`、`ratio` 两种量纲？按字面适用于所有非精确比较的数值。实测：金额列参考 12.34、候选 1234，判对 | 按字面：除整数型计数外都试 ×100、÷100。**建议裁定只限 percentage、ratio** |
| 2 | 三.3 | 量纲为 `other` 的整数列（年份、未标为编码的键、月份）走 0.5% 相对容差：2008 与 2009 相差 0.05%，判为相等。实测：三年长表（品类、年份、比率）把每行年份错后一年，判对。长表里的年份列（如 Q83、Q90、Q110）都有这个风险 | 按字面。**建议整数型的 other 列精确比较，或在题库里把这类列标为编码** |
| 3 | 二 | 除 `required_columns`、`value_kinds`、`value_types` 外，`ordered`、`top_n`、`tie_columns` 是否也必填？未知字段要拒绝还是忽略？ | 都必填；未知字段拒绝。有 `top_n` 而 `tie_columns` 为空时也拒绝 |
| 4 | 五.7 | `selection` 的 `where` 条件列要不要也必答（要靠它判断候选行属于哪一路）？ | 要求必答，否则拒绝 |
| 5 | 五.3 | 参考的严格前缀与边界怎么定：按参考的物理行序取第 N 行的并列键？域不足 N 时候选应给几行？ | 取物理第 N 行的并列键（`quantize_tie`），其后各行必须都是这个键，否则拒绝 rules；域不足 N 时候选给出全部行 |
| 6 | 一.4 | 原因码：列数够、但没有任何对应过得了筛选时，给 `missing_columns` 还是 `values`？多种对应都失败时取哪一个的原因？多份参考取哪一份？ | `missing_columns` 只用于提前拒绝；其余给 `values`。多种对应取走得最远的（values < order < selection < rank）；多份参考取第一份 |
| 7 | 六.5 | 未命中的对应要试满 1,000 种才判 `unscored`，而「试了多少种」取决于各自筛选的强弱和顺序。两套实现在「`wrong` 还是 `unscored`」上可能分歧（压力用例 identical-columns-wrong-cap 就是这种情形） | 照第十一节第 4 条。真实语料 3,645 条里没有一条命中上限 |
| 8 | 三.7 | 拼接顺序（前后 / 后前）是整份答案统一，还是逐行可变？名字有一部分为 NULL 时怎么拼？合列能不能用在编码列、名次列、成对列或选择身份列上？ | 整份统一；有 NULL 的部分不拼，视为不相等；以上几种列不参与拆合 |
| 9 | 三.6 | 参考为空串、候选为 NULL 算不算匹配（规则说「任意字符串」，NULL 不是字符串）？日期列算不算「非数值列」？编码列适用吗？ | 不匹配；日期列适用；编码列不适用（编码精确比较） |
| 10 | 三.5 | 只列了 `YYYY-MM-DD 00:00:00` 字符串。带 `T` 的写法、带小数秒的零点，以及编码列里的日期怎么算？ | 带 `T` 或小数秒的字符串不等价；编码列里的日期照样归一 |
| 11 | 五.4 | 有多个计数列时是否都要为 0？「其余必答数值」是否包括名次列（名次不为 0，会让这条宽容失效）？有序结果里多出或缺少的零行能出现在任何位置吗？ | 全部计数列为 0；包括名次列；有序时零行可以在任何位置 |
| 12 | 五.9 | 名次写成 `1.0` 或 `"1"` 算不算整数？一份答案有两列名次时，是否要用同一种写法？位置写法遇到非前缀排名（Q119 一类）怎么核？ | `1.0` 算，`"1"` 不算；两列名次用同一种写法；非前缀排名只要求块内不重复、落在块的范围内 |
| 13 | 五.5 | 成对的两组列只有一侧必答时怎么办？ | 只在两侧都必答的位置上允许对调 |
| 14 | 一 | 候选各行宽度不同、参考为空时怎么判？布尔值能不能与 0、1 比？ | 宽度不同报错；参考为空时，只有候选也为空才判对；布尔值只等于布尔值 |
| 15 | 五.7 | 选择身份列在行的比较里也应精确（选择契约写「身份不享受 0.5%」），规格 v2 没有重述 | 身份列在所有比较里都精确 |

**语料格式**：按 #105 的说明可以读。三处缺口：
- **数组、元组单元格**：ClickHouse 的 Array、Tuple 会编码成 JSON 列表，与「行」的嵌套列表分不出来。目前语料里没有这类值。
- **时间戳**：`$datetime` 的小数秒和时区按 `isoformat` 保留，能读，但规格没定义它们与日期的关系，见第 10 条。
- **题库版本**：语料的 rules 是导出时的 `eval-v1.1`；按规格第五节第 7 条，Q74、Q98、Q117、Q119 的 rules 会被拒绝。检查器加了 `--rules-from`，可以换用 `eval-v1.2`（题库 PR #20）的 rules 读入。建议正式对账前按 `eval-v1.2` 重新导出语料。

## 五、跑出来的结果
