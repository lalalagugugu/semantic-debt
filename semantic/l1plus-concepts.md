状态：**用户已审定（2026-10-23）**：⚑ 六项全部按建议；其余条目不删不补。正文已写入 `semantic/l1plus.yaml`。

审定后第 3 步核数据时改了两处事实（不是改设计）：

- **E04**：国家 / 地区是 34 个，不是 35 个。

## 这份清单是怎么来的

和汇总层的需求清单（`semantic/summary/requirements.md`）同样的做法：设想这家零售公司的
管理层、财务、门店运营、电商、客户运营、商品六类读者做**常规经营分析**时会用到、而 L1 里
还没有定义的概念，按三类列出：派生概念、需要别名的实体、类层次。

来源只有 `semantic/source.yaml`、`semantic/conventions.md` 和 `semantic/profiling/out/`。
写清单的会话是盲模式，没有看过题库和任何运行结果，也不知道之后会被问什么。

每条只写名称、一句话用途、拟定义。第 3 步写正文时，定义要写到能直接写成一条 SQL，
并写出适用条件与例外。拟定义里引用的 `A..` 是 `semantic/l1plus-audit.md` 的条目编号。

## 请用户看什么

1. **删**：哪些概念不是这家公司常规会用的（标了「可选」的是我拿不准的）。
2. **补**：有没有明显缺了的常规概念。
3. **定**：标了 ⚑ 的条目有一个需要你拍板的取值（阈值、范围）。我给了建议值。

和汇总层一样：**不要**按记得的题目增删。

## 一、派生概念

### 客户（全部落在线上销售；「购买」与约定 13、14 一致，含只有退货的行，除非另写）

| # | 名称 | 用途 | 拟定义 |
|---|---|---|---|
| D01 | 首购日 | 新客、队列的基础 | 该客户在线上销售里全部行的最小日期（约定 14 已用，这里单独命名） |
| D02 | 末购日 | 客户分层的基础 | 该客户全部行的最大日期（约定 13 已用，单独命名） |
| D03 | 首购队列 | 按首购时间给客户分批，看各批后续表现 | 客户按首购日所在的月（或季、年）归入一个队列；队列规模 = 该队列的客户数 |
| D04 | 队列留存率 | 看某批客户之后还在不在买 | 某队列在其后第 k 期仍有购买的客户数 ÷ 队列规模；期的长度与队列相同 |
| D05 | 复购客户 ⚑ | 电商最常看的忠诚度指标 | 窗口内有 ≥ 2 个不同订单号的客户。⚑ 只有退货行的订单算不算一次购买：**建议只算有销售行（`SalesQuantity > 0`）的订单**，因为「复购」说的是再次购买，不是退货 |
| D06 | 复购率 | 同上 | 窗口内复购客户数 ÷ 窗口内有购买的客户数 |
| D07 | 购买频次 | 客户买得多勤 | 每个客户窗口内的订单数；按客户求平均即「客均订单数」（L1 已有） |
| D08 | 客户累计消费 | 客户价值排名 | 客户截至 2009-12-31（或窗口末）的销售额合计 |
| D09 | 客户流失率 / 活跃率 | 客户分层的比率版 | 已流失（或活跃）客户数 ÷ 客户总数，分层按约定 13 |
| D10 | 客户年龄与年龄段 ⚑ | 客户画像 | 年龄 = 2009 − 出生年（理由见自查文末）。⚑ 年龄段：**建议** 30 岁以下、30–39、40–49、50–59、60 岁及以上 |
| D11 | 收入档 ⚑（可选） | 客户画像 | ⚑ **建议**按 `YearlyIncome` 分四档：< 40,000、40,000–79,999、80,000–129,999、≥ 130,000（10,000,000 那一档落在最高档） |

### 销售与时间

| # | 名称 | 用途 | 拟定义 |
|---|---|---|---|
| D12 | 月均销售额 | 跨不同长度的期比较 | 先按月汇总，再对月数求平均（约定 4 的月版本） |
| D13 | 累计销售额（年初至今 / YTD） | 月报、季报的累计列 | 本年 1 月 1 日到期末日的销售额；「截至某月累计」同理 |
| D14 | 同比增长额、环比增长额 | 与增长率配套 | 本期销售额 − 对比期销售额（对比期按 A08） |
| D15 | 年复合增长率（可选） | 三年趋势 | (末年 ÷ 首年)^(1 ÷ 年数差) − 1；本库 2007 → 2009 年数差为 2 |
| D16 | 连带率（每单件数） | 零售常用的客单结构指标 | 销售数量 ÷ 订单数（只有线上有订单） |
| D17 | 退货金额率（可选） | 用金额看退货 | 退货金额 ÷ 销售额。**名字刻意不叫「退货率」**，「退货率」仍按约定 7 是数量之比 |
| D18 | 销售排名 / 前 N 名 | 排行榜 | 按指标降序取前 N；并列时按名称升序，结果恰好 N 行 |
| D19 | ABC 分类（帕累托）⚑ | 商品分级管理 | 按销售额降序累计占比：⚑ **建议** A 类 = 累计 ≤ 80%、B 类 = 80%–95%、C 类 = 其余；分母按 A21 |
| D20 | 动销产品与动销率 | 商品经营 | 动销产品 = 窗口内销售数量 > 0 的产品；动销率 = 动销产品数 ÷ 在售产品数（在售按 A31） |
| D21 | 滞销产品 ⚑ | 商品经营、清库存 | 在售、当前有在手库存、但窗口内没有销售的产品。⚑ 窗口：**建议**没说时取近 90 天 |

## 三、类层次

把 L1 散在各处的层级与划分集中写成类与子类。第 3 步在 L1+ 里写成文字，在 L3a 里写成
OWL 类与 SHACL 约束（同一份内容）。

| # | 层次 | 拟写法 |
|---|---|---|
| H01 | 销售记录 | 销售记录 ⊃ 线上订单行（⊃ 销售行、退货行）、全渠道汇总行；两类记录的线上部分口径不同、不得相加 |
| H02 | 门店 | 门店 ⊃ 实体店（299）、虚拟门店（⊃ 线上店 3、经销店 3、目录店 1）；另一个划分：营业中 / 已关店。门店类型 ↔ 渠道一一对应 |
| H03 | 产品 | 品类 ⊃ 子类 ⊃ 产品；另有「未登记产品」（事实表引用、产品表没有的 284 个键）；另一个划分：在售 / 停售 |
| H04 | 地理 | 大洲 ⊃ 国家 / 地区 ⊃ 省州 ⊃ 城市；客户所在地与门店所在地是两种「位于」关系 |
| H05 | 计划实体 | 集团 ⊃ 国家 / 地区 ⊃ 州 ⊃ 门店实体（只有门店实体有计划行；线上店、目录店直接挂在国家下） |
| H06 | 员工 | 销售总监 ⊃ 大区经理 ⊃ 州经理 ⊃ 门店经理（按 `ParentEmployeeKey`） |
| H07 | 科目树 | 完整的 24 个科目父子树，标出叶子科目与顶层科目（第 3 步从数据查出，A33） |
| H08 | 客户 | 客户按约定 13 分成活跃 / 有流失风险 / 已流失（互斥且覆盖全部）；新客（约定 14）、复购客户（D05）是另外两个子集 |
| H09 | 交易的促销状态 | 无折扣交易（PromotionKey 1）/ 打折交易（⊃ 9 个促销名 × 3 个年份） |
| H10 | 场景 | Actual / Budget / Forecast；Budget = 正式目标与正式预算 |
| H11 | 日子类型 | 工作日 / 周末（本库节假日 = 周末）；季节按大洲各一套 |
| H12 | 库存状态 | 门店 × 产品组合按当前快照：零库存 ⊂ 低于安全库存 ⊂ 全部组合（零库存是否全部低于安全库存：安全库存最小值是 3，所以是） |
| H13 | IT 设备与成本 | 设备 ⊃ POS、服务器、集线器、路由器；成本 ⊃ 设备购置费、年度维护费 |
