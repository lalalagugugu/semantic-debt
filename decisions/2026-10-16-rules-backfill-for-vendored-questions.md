# 2026-10-16 外部基准那 100 题缺 `rules`，必须在 `eval-v1` 之前补齐

- 发现者：T11（接上真实题目格式时）
- 影响：T05、T06（题库）、T13 起的全部运行、T19
- 状态：**待 Codex 落实**，必须在 G2（`eval-v1` 冻结）之前

## 问题

题库里**只有 22 道新题带 `rules`**，外部基准带进来的 100 道一条都没有；manifest 里也没有 `ordered` 字段。于是 harness 构造不出 `rules`，只能原样透传空值。

后果是**三条已裁决的评分规则对那 100 题静默失效**：

| 缺的字段 | 失效的规则 | 后果 |
|---|---|---|
| `ordered` | 冻结规则第 4 条（只有问句要求排序时才比行序） | 行序比不比全凭默认值，而 T02 已经因为「拿参考结果碰巧的物理行序当判据」被独立复核判为契约缺陷 |
| `top_n`、`tie_columns` | 第 4 条的「前 N 名并列任一都算对」 | Top-N 题的边界并列无法判定 |
| `value_kinds` | `decisions/2026-10-14-...` 第四节（近零量的绝对容差下限） | 近零量的相对误差照样炸开，实测可达 17.13% |
| `value_types` | 同上第八节（计数精确相等的整数类型守卫） | 守卫失效，计数仍按 0.5% 相对容差，会放过扇出型 join 错误 |

**这不是小事**：100/122 的题目用的是没有这些保护的评分口径，而那四条规则正是 T02 花了四轮才定下来的。

## 要做什么

1. **把 `rules` 补齐到全部 122 题**，不只是新增的 22 题。
2. `ordered` 的判定沿用已裁决的口径：**题目元数据要求排序 且 参考 SQL 有最终外层 ORDER BY**，二者缺一为 `false`；不得拿参考结果碰巧的物理行序当判据。`scripts/validate_scorer.py` 里已有这套判定（`ORDERED_QUESTION_IDS` + `final_order_clause`），把它的结果**持久化进题目记录**，而不是每次临时算。
3. `value_kinds`：新题按 T05 卡的要求**显式声明**；外部 100 题用 `infer_value_kind` 推断，但**逐题列出推断结果供人工过目**（词表是对着英文列名建的，这 100 题正是英文原题，命中率应该高，但要看过）。
4. `value_types` 从参考查询的返回类型取——整数计数守卫依赖它。
5. Top-N 题要带 `top_n` 与完整边界并列组，并按**全局固定精度量化**（跨引擎可复现，T05b 用 pandas 重算要对得上）。

## 为什么必须在 G2 之前

`eval-v1` 冻结的是题集、参考答案、划分与覆盖标注。`rules` 是参考答案的一部分——冻结之后再补，等于冻结了一个不完整的东西；而 T13 起的所有运行都按 `eval-v1` 打分，补得晚就要全部重打分。

## 交叉检查

T05b（Claude Code 用 pandas 独立重算）会一并核对：补出来的 `ordered`、`top_n`、边界并列组能否跨引擎复现。两家对不上的题，按已有裁决**不得带着 Top-N 并列进入 `eval-v1`**。
