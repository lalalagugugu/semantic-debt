# 2026-10-18 只按题目问到的列判分（T12-1）；模型选择

- 裁决人：用户，2026-10-18（原则由用户提出：「不应该用题目没问的列作为判错的依据；从 token 效率看，也不该鼓励模型输出题目没问的内容」；协调会话补实施方案）
- 约束：T02（评分器，Codex）、T05/T06（题库，Codex）、T05b、T12、G3（`harness-v1`）；题库需重新冻结（`eval-v1.1`）
- 来源：T12 试跑（open question T12-1）。SQL-L1 上 `missing_columns` 判错 Pro 16 次、Flash 4 次：参考带着题目没问的列（Q70、Q80 多门店数或客户数，Q81 多总额），模型只答所问被判错；Q50 反过来，参考缺了题目问的「增长额」。把参考投影到候选给出的列上诊断（评分器未动），SQL-L1 的上界是 Flash 约 54%、Pro 约 47–52%

## 一、原则

1. **判分只看题目问到的列。** 没问的列不能作为判错依据。
2. **参考必须包含题目问到的每一列。** 缺了就是参考错误（Q50 一类），补上。
3. **候选多给的列照旧不扣分**（评分器现行规则），但系统提示**不鼓励**多给，现有提示保持中性，不改。

## 二、实施：每份参考标出「必答列」

1. 每份参考在 `rules` 里写 `required_columns`（参考输出列的位置，从 0 开始）。必答列 = 题目问到的量 + 题目要求列出的对象的标识列（标识用键还是名称，沿用 `2026-10-17-one-convention-one-answer.md` 第二节「展示方式只留一份」）。
2. 其余列是**非必答列**，保留在参考里，不删：Top-N 的排序键、筛选依据的值等。评分时参考先投影到必答列再比；`rules.order_by` 可以指向非必答列，它只在参考一侧用来划分并列块，候选不必给出。
3. 没写 `required_columns` 的参考，全部列都算必答（与现行规则一致），评分器告警，不得静默放宽。
4. judge 题不受影响。
5. 不得按题特判；评分器只读 `rules`。

## 四、模型选择

卡片规则「Flash 低于 50% 或 Pro 高 10 个点以上就选 Pro」的前提是 Pro 更强，试跑结果相反：严格口径 SQL-L1 Flash 47.6%、Pro 32.3%，按必答列的上界 Flash 约 54%、Pro 约 47–52%，两种口径下 Pro 都不高于 Flash，每次调用成本却是 Flash 的约 7.5 倍。**选 Flash**（`deepseek-flash`，指纹 `e72d3c7f663d3e1383b00b3884cb4501`）。规则字面上的触发（47.6% < 50%）来自本次要修的列口径，不作数。T12 把理由写进 `decisions/model.md`；Pro 的缓存过期探测不跑。
