# 2026-10-18 展示约定写进系统提示：用名称标识对象、不截断、不改写分类值

- 裁决人：用户，2026-10-18（原则由用户提出：只给键算不算错，取决于 harness 有没有提出这个要求；要求了还给编码是指令遵循问题，可以扣分；没要求就不能算 SQL 有问题。协调会话补实施方案，合并即同意）
- 约束：T12、G3（`harness-v1`）、T13 起的全部运行、T19
- 补充：`decisions/2026-10-18-reference-columns-asked-only.md` 第五节（必答的标识列一律是名称）

## 一、问题

第五节规定必答的标识列是名称，只给键的作答判错。但现行系统提示（`harness/prompt.py` 的 `SYSTEM_PROMPT`）对结果怎么标识对象一字未提。模型用键标识对象、数值全对，判它错，扣的不是 SQL 能力，而是一条我们没有告诉它的要求。试跑里已知至少两次（Q117 Pro SQL-R r3、Q34 Pro SQL-L1 r3）。

## 二、裁决

1. **系统提示加一条作答要求**（所有单元相同，不针对任何题）：

   > 查询结果是给业务人员看的：结果里要列出具体对象（如门店、产品、客户、员工）时，用名称标识；可以同时给编码，但不要只给编码。

   措辞由 T12 实现时可微调，不得点名具体表或字段。
2. **评分不变**：必答的标识列仍是名称。新提示下只给编码的作答判错，归因时归为「指令遵循」，与 SQL 写错分开统计。
3. **试跑（旧提示）不扣这一项**：最终重评时，只给编码、没给名称的作答，由 T12 在 chDB 上把编码映射成名称后核对；其余全对的，在试跑结果里计为正确，并单列「旧提示下只给编码」的条数。只用于选模型，不改评分器。
4. 改系统提示会让每个单元的缓存前缀变一次，冷启动费用可忽略（T12 实测每轮全部单元约 0.16 元）。
5. 在 G3 前合并，随 `harness-v1` 冻结。T19 披露这条要求何时、为何加入。

## 三、同类的展示差异一并处理（协调会话排查试跑判错后补充）

原则（用户提出）：几种做法都没错、只是没统一，又与理解意图、写对 SQL 无关的展示差异，统一写进系统提示；评分器已有通用规则兜底的，不重复写。协调会话逐条看了试跑 288 条作答中的判错：

| 差异 | 试跑中的例子 | 处理 |
|---|---|---|
| 只给编码、不给名称 | Q117、Q34 | 系统提示，见第二节 |
| **自行截断结果**：题目要完整清单，作答加了题目没要求的 `LIMIT` | Q75（1,470 行的答案只给了前 100 行） | **系统提示加一句**：除非问题要求前 N 名，不要截断结果 |
| **自造或翻译分类标签**：把数据里的取值改写成自己起的名字 | Q68、Q17（`IsHoliday = 'Yes'` 改写成「节假日 / 非节假日」） | **系统提示加一句**：数据里有的分类值照原值输出，不翻译、不改写；需要自己分组时，组名用语义上下文里的叫法。T12 实现前先核对这两题参考里的标签写法，确认这条与参考一致 |
| 空值分组改标成「未知」「Unknown」 | Q102、Q76、Q74、Q34 | 不进提示，由评分器第二节第 1 条兜底（`decisions/2026-10-18-label-scoring-and-all-wrong-audit.md`）；强制展示 NULL 对业务读者不自然 |
| 人名拆成名、姓两列 | Q82、Q100 | 不进提示，评分器第七节第 2 条兜底 |
| 百分比写成 0.13 或 13 | Q69、Q76 | 评分器已接受 |

不属于这一类、照常判错的：渠道或门店范围、差额方向、起算日期等口径选择（如 Q74 是否含虚拟门店、Q73「差额」的方向、Q82 任期起算日）——这些正是语义层要回答的问题。

试跑（旧提示）里因截断或自造标签判错的作答，与第二节第 3 条同样处理：最终重评时 T12 单列，能核对的按内容核对，不计入「模型真错」。

本排查只覆盖试跑的 24 题；T12 最终重评的逐条归因里设「展示差异」一类，G3 前若再发现同类问题，同样进提示；G3 之后系统提示冻结，只能在报告里注明。

## 三之二、全库排查后的定稿（用户同意，2026-10-18）

T05b 按用户要求排查了全部 122 题（含 judge），报告 `reports/presentation-conventions-scan.md`（#86，只含题号、类别、计数）。用户同意按协调会话的意见处理，类别编号沿用报告：

**写进系统提示**（通用约定，不点名任何题、表或字段；T12 实现，措辞可微调）：

| 类 | 约定 |
|---|---|
| 1 | 列出具体对象、或按某个维度分组时，用名称标识；可同时给编码，不要只给编码（第二节第 1 条扩到按维度分组） |
| 2 | 问题没要求前 N 名时，不截断结果 |
| 3 | 数据里有的分类值照原值输出，不翻译、不改写 |
| 4（部分） | 需要自己分组时，组名用语义上下文里的叫法 |
| 5 | 比较多个组时每组一行，不要把组转成列 |
| 6 | 不附加问题没要求的合计、小计行 |
| 7 | 日期写成 YYYY-MM-DD；按月、季、年的期间写成语义上下文里对应字段的取值形式 |
| 8 | 金额用数据的原始单位，不换算成万元等；数值不写成带格式的字符串 |
| 9b | 变化率写成（本期 − 基期）÷ 基期，不写成两期之比 |
| 9d | 降幅、缺口等「减少了多少」的量用正数表示 |

**统一参考写法**（Codex，与 `required_columns` 同一个题库 PR，进 `eval-v1.1`；T05b 复核）：第 5 类（统一为长表）、第 7 类（日期与期间按上表）、第 10 类（空值与 0 按数据事实统一）、第 13 类（成对对象在参考规则里标为无序对）。

**评分器通用规则**（Codex，与标签规则同一个 PR）：第 7 类「日期与当天零点的时间戳等价」；第 11 类「计数为 0 的组可有可无」。

**不处理**：第 4 类中题面已给标签的（Q84、Q115、Q120）与 Q85、Q48（一一对应规则可能把对调的标签判对；两题分别是低区分度与 judge，不进主表）；9a（评分器已接受）；9c（Q50、Q99，属必答列裁决）；第 10 类不在评分器里把空值等同于 0（「没有数据」与「为 0」业务含义不同）；第 12 类（评分器已兜底）。
