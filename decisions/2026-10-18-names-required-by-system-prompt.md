# 2026-10-18 「用名称标识对象」写进系统提示；只给编码按指令遵循判错

- 裁决人：用户，2026-10-18（原则由用户提出：只给键算不算错，取决于 harness 有没有提出这个要求；要求了还给编码是指令遵循问题，可以扣分；没要求就不能算 SQL 有问题。协调会话补实施方案，合并即同意）
- 约束：T12、G3（`harness-v1`）、T13 起的全部运行、T19
- 补充：`decisions/2026-10-18-reference-columns-asked-only.md` 第五节（必答的标识列一律是名称）

## 一、问题

第五节规定必答的标识列是名称，只给键的作答判错。但现行系统提示（`harness/prompt.py` 的 `SYSTEM_PROMPT`）对结果怎么标识对象一字未提。模型用键标识对象、数值全对，判它错，扣的不是 SQL 能力，而是一条我们没有告诉它的要求。试跑里已知至少两次（Q117 Pro SQL-R r3、Q34 Pro SQL-L1 r3）。

## 二、裁决

1. **系统提示加一条作答要求**（所有单元相同，不针对任何题）：

   > 查询结果是给业务人员看的：结果里要列出具体对象（如门店、产品、客户、员工）时，用名称标识；可以同时给编码，但不要只给编码。

   措辞由 T12 实现时可微调，不得点名具体表或字段。
2. **评分不变**：必答的标识列仍是名称。新提示下只给编码的作答判错，归因时归为「指令遵循」，与 SQL 写错分开统计。
3. **试跑（旧提示）不扣这一项**：最终重评时，只给编码、没给名称的作答，由 T12 在 chDB 上把编码映射成名称后核对；其余全对的，在试跑结果里计为正确，并单列「旧提示下只给编码」的条数。只用于选模型，不改评分器。
4. 改系统提示会让每个单元的缓存前缀变一次，冷启动费用可忽略（T12 实测每轮全部单元约 0.16 元）。
5. 在 G3 前合并，随 `harness-v1` 冻结。T19 披露这条要求何时、为何加入。
