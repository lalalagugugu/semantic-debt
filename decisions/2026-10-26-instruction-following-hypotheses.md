## 一、假设一：被测模型的指令遵循偏弱（下一期检验）

可能同时解释本期的四个现象：

1. 按约定交付率明显低于内容准确率（呈现差异在 L1plus 判错中约占一半）；
2. B2 中声明的假设与提交的结果明确矛盾（撤销 11 次，多于新认可 5 次）；
3. T29 扩展试跑中，答错扣分加到 100 倍、规则移到系统消息最前，仍 0 拒答；
4. T29 的 C 组 49 次中 13 次漏写要求的「把握」行。

## 二、假设二：「前沿模型显得聪明」主要来自其上层 harness，而非模型本身（下一期检验）

对照假设一的替代解释：各家经 API 提供的模型在指令遵循上差距不大，Claude Code、Codex 等产品的表现主要来自上层的工具循环、校验和长提示。检验方式：多家模型都经官方 API（不经厂商的编程工具）、套用本实验同一套 harness，比较内容准确率、按约定交付率、拒答行为和假设一致性。只有这样比较才是同条件对比。

两个假设都写入中期报告的「局限与下一期」，不作结论。

## 三、跨单元结论的稳健性检查（本期）

**问题**：指令遵循偏弱如果在各单元间程度不同（例如某些单元的上下文恰好更容易或更难遵守交付约定），跨单元比较会混入交付差异。调优补丁直接教了交付格式，是已知的一处混入。

**做法**：双口径重算后，对本期主要比较逐一在两种口径下给出差值与按题配对自助法区间（参数同 `reports/results/tuning.md`）：L0 / R / L1 / L1c / L1.5W / L1.5S / L2 / JSON-L2 之间的主比较、直答与探查 agent、L1 与 L1plus、L1plus 与 L3a、L1 与两个调优单元、调优单元之间、L1plus 与叠加单元。

**判据**（结果前写定）：

- 两种口径下差值方向相同、且区间是否含 0 的结论相同：记为「稳健」；
- 方向相同但区间结论不同：记为「强弱依口径而定」，报告两种口径的数字；
- 方向相反：记为「依赖交付口径」，原结论在报告中撤回或改写。

中期报告按此标注每条跨单元发现，并如实披露：只测了一个模型，结论能否推广到其他模型待下一期检验。
